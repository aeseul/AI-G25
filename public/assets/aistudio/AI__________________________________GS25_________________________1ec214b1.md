# AI 편의점 꿀조합 큐레이터
## Google AI Studio Build 모드용 추가 개발 명세서
### 실제 진입 흐름은 유지하고, 선택한 매장 다음부터 가상 GS25 공간 구현하기

> **사용 방법:** 현재 작업 중인 Google AI Studio 프로젝트의 Build 모드에 아래 명세를 입력한다. 기존 앱을 초기화하지 말고 현재 프로젝트에 이어서 수정하도록 한다.

## 개발 방향

로그인·기존 위치 검색·매장 선택 등 이미 구현한 앞부분은 유지한다. 사용자가 매장을 선택한 다음부터는 실제 GS25의 비공개 상품·재고 시스템 대신 앱 내부의 **가상 GS25 매장 공간**으로 진입시킨다. 가상 매장 안에서 상품 탐색, 행사 확인, 재고 확인, 예산별 꿀조합 추천, 레시피, 장바구니, 가상 구매를 체험하게 한다.

# Studio 입력용 개발 프롬프트

너는 기존 React/TypeScript 앱을 이어서 개발하는 숙련된 풀스택 개발자이자 UX/UI 디자이너다.

현재 프로젝트는 **AI 편의점 꿀조합 큐레이터**이며 로그인 및 매장 선택 등 앱의 앞부분이 이미 구현되어 있다. 기존 프로젝트를 분석한 후 아래 요구사항을 추가 구현하라.

## 1. 반드시 지켜야 할 작업 원칙

1. 기존 프로젝트를 새로 생성하거나 초기화하지 않는다.
2. 현재 구현된 로그인, 회원가입, 사용자 상태, 위치 검색, 매장 선택, 상단 헤더 및 디자인을 최대한 유지한다.
3. 정상 작동하는 기존 기능을 삭제하거나 임의로 변경하지 않는다.
4. 매장 선택 후에는 앱 내부의 **가상 GS25 매장 공간**으로 진입시킨다.
5. 가상 매장의 상품·가격·행사·재고는 모두 테스트용 시뮬레이션 데이터다. 실제 GS25 공식 판매정보나 실시간 재고인 것처럼 표현하지 않는다.
6. Gemini 유료 API를 호출하지 않아도 핵심 기능 전체가 작동하도록 자체 데이터와 규칙 기반 추천 로직을 구현한다.
7. Firebase가 이미 연결되어 있다면 기존 설정을 보존한다. 연결되지 않은 기능을 연결 완료라고 표시하지 않는다.
8. 모든 버튼과 입력은 실제로 작동하게 한다.
9. 기존 크림색·초록색·주황색 디자인을 유지한다.
10. 변경 후 TypeScript 오류, 실행 오류, 콘솔 오류를 확인하고 수정한다.

## 2. 전체 사용자 흐름

```text
로그인 / 회원가입
       ↓
기존 메인 화면
       ↓
현재 위치 확인 및 주변 매장 탐색
       ↓
매장 선택 (예: GS25 망원마젤란점)
       ↓
가상 GS25 매장 공간 입장
       ↓
상품 탐색 / 행사 상품 / 가상 재고 확인
       ↓
예산·맛·식사 상황 선택
       ↓
가상 상품 DB 기반 꿀조합 추천
       ↓
추천 조합 상세 및 3분 레시피
       ↓
장바구니 / 예산·잔액 확인
       ↓
가상 구매 완료 / 가상 영수증
```

### 실제 기능과 가상 시뮬레이션의 경계

| 영역 | 구현 방식 |
|---|---|
| 로그인 및 회원 인증 | 기존 구현 및 Firebase 설정 유지 |
| 사용자 위치 권한 | 브라우저 Geolocation 사용 |
| 주변 매장 탐색 | 기존 지도/장소 검색 기능 유지 |
| 매장 선택 | 기존 매장 선택 흐름 유지 |
| 선택 매장 내부 상품 | 가상 상품 데이터베이스 |
| 매장별 재고 | 가상 재고 데이터 |
| 1+1·2+1 행사 | 가상 행사 데이터 |
| 메뉴 추천 | 자체 규칙 기반 알고리즘 |
| 가격·잔액 계산 | 코드에서 계산 |
| 구매 완료 | 가상 구매 및 재고 차감 |
| 실제 결제 | 구현하지 않음 |

사용자가 실제 위치에서 매장을 선택하더라도 해당 매장의 실제 재고를 확인한 것이 아니다. 매장 선택은 가상 매장 체험을 시작하기 위한 진입 정보로만 사용한다.

## 3. 가상 매장 입장 화면

기존 매장 선택 화면에서 매장을 선택한 뒤 **「이 매장 둘러보기」** 또는 기존 매장 선택 버튼을 누르면 가상 매장 홈으로 이동시킨다.

### 가상 매장 기본 정보

- 표시 브랜드: GS25
- 표시 매장명: 앞 화면에서 사용자가 선택한 매장명
- 내부 매장 ID: `GS25_DEMO_001`
- 데이터 유형: `DEMO`
- 상태 문구: `가상 매장 체험 중`
- 안내 문구: `상품·가격·재고·행사 정보는 앱 테스트용 가상 데이터입니다.`

실제 매장명을 표시하더라도 해당 매장의 실재고·판매상품과 연결되었다고 오해하지 않도록 가상 데이터 안내를 눈에 띄게 표시한다.

### 가상 매장 홈 구성

상단:
- GS25 로고 또는 텍스트형 브랜드 표시
- 선택된 매장명
- `가상 매장` 표시
- 현재 예산 요약(기본 5,000원)

메인:
- 환영 문구: `어서 오세요! 오늘은 5,000원으로 어떤 한 끼를 만들어볼까요?`
- 메뉴 카드 4개: 전체 상품 보기 / 1+1·2+1 행사 보기 / AI 꿀조합 찾기 / 내 장바구니
- 오늘의 추천 조합 카드
- 카테고리 바로가기
- 가상 매장 안내

실제 편의점에 들어온 듯한 경험을 주되, 상품을 빠르게 찾고 추천으로 이동할 수 있는 깔끔한 모바일 쇼핑 UI로 만든다.

## 4. 가상 상품 데이터베이스

외부 API 없이 앱 내부의 초기 데이터로 작동하게 한다. 상품 데이터는 UI 코드와 분리된 별도 데이터 모듈로 관리한다.

다음은 모두 **개발용 예시 상품 및 예시 가격**이다.

| ID | 상품명 | 카테고리 | 가격 | 초기 재고 |
|---|---|---|---:|---:|
| `P001` | 불닭볶음면 | 면류 | 1,800원 | 10 |
| `P002` | 육개장 사발면 | 면류 | 1,200원 | 8 |
| `P003` | 참치마요 삼각김밥 | 즉석식품 | 1,200원 | 12 |
| `P004` | 전주비빔 삼각김밥 | 즉석식품 | 1,200원 | 10 |
| `P005` | 스트링치즈 | 유제품 | 1,500원 | 7 |
| `P006` | 훈제란 1구 | 계란 | 1,000원 | 9 |
| `P007` | 바나나우유 | 음료 | 1,500원 | 6 |
| `P008` | 생수 500ml | 음료 | 800원 | 15 |
| `P009` | 초코바 | 간식 | 1,000원 | 10 |

각 상품은 다음 필드를 가진다.

- `id`, `brand`, `name`, `category`
- `regularPrice`
- `promotionType`, `promotionDescription`, `promotionStartAt`, `promotionEndAt`
- `stockQuantity`, `availabilityStatus`
- `tasteTags`, `mealTags`
- `isMicrowaveSuitable`, `requiresHotWater`, `estimatedPrepMinutes`
- `imageUrl` 또는 기본 상품 이미지
- `dataSource: "DEMO"`
- `lastVerifiedAt`

이미지 URL이 없는 상품은 깨진 이미지 대신 카테고리별 기본 이미지나 플레이스홀더를 보여준다. 상품 데이터는 추후 Firebase Firestore로 옮길 수 있도록 데이터 접근 계층을 분리한다.

## 5. 상품 탐색 화면

다음 기능을 구현한다.

- 전체 상품 목록
- 카테고리 탭: 면류 / 즉석식품 / 유제품 / 계란 / 음료 / 간식
- 상품명 검색
- 가격순 정렬
- 재고 있는 상품만 보기
- 행사 상품만 보기
- 상품 카드에 상품명, 가격, 행사 배지, 가상 재고 상태 표시
- 상품 상세 보기
- 장바구니 담기

상품 카드 예시:

```text
[상품 이미지]
불닭볶음면
1,800원
재고 있음 · 10개
[장바구니 담기]
```

재고 수량은 가상 데이터임을 화면에서 명확히 표시한다.

## 6. 가상 행사 시스템

초기 행사 데이터:

| 상품 | 행사 유형 | 시뮬레이션 규칙 |
|---|---|---|
| 바나나우유 | 1+1 | 동일 상품 2개 구매 시 1개 가격 |
| 초코바 | 2+1 | 동일 상품 3개 구매 시 2개 가격 |
| 나머지 상품 | 행사 없음 | 정상 가격 |

행사 계산은 코드에서 수행한다. 행사 배지와 적용 조건을 명확하게 보여준다.

계산 예시:
- 바나나우유 1개: 1,500원
- 바나나우유 2개: 1,500원
- 초코바 2개: 2,000원
- 초코바 3개: 2,000원

행사 적용 수량과 실제 결제 수량을 구분한다. 행사 조건이 충족되지 않은 수량에 임의로 할인을 적용하지 않는다.

## 7. 가상 재고 관리

- 재고 5개 이상: `재고 있음`
- 재고 1~4개: `소량 재고`
- 재고 0개: `품절`

동작:
1. 상품을 장바구니에 추가할 때 현재 가상 재고를 확인한다.
2. 재고보다 많은 수량을 담지 못하게 한다.
3. 품절 상품은 장바구니에 추가할 수 없게 한다.
4. 가상 구매 완료 시 구매 수량만큼 재고를 차감한다.
5. 차감된 재고는 화면에 즉시 반영한다.
6. 새로고침 후에도 개발 중 재고가 유지되도록 로컬 저장 방식을 사용한다.
7. 개발 테스트용 `가상 재고 초기화` 기능을 제공할 수 있다.

재고 차감은 실제 GS25 매장에 영향을 주지 않는 로컬 시뮬레이션이어야 한다.

## 8. 꿀조합 추천 입력 화면

가상 매장 홈에서 `AI 꿀조합 찾기`를 누르면 추천 조건 입력 화면으로 이동한다.

### 예산
- 기본값 5,000원
- 빠른 선택: 3,000원 / 5,000원 / 7,000원
- 직접 입력 가능
- 0원 이하 및 잘못된 숫자 입력 방지

### 맛 테마
- 매콤 / 고소 / 단짠 / 담백 / 새콤 / 달콤 / 고단백
- 복수 선택 가능

### 식사 상황
- 한 끼 식사 / 야식 / 간식 / 안주 / 해장

### 추가 선호
- 1+1 행사 우선
- 2+1 행사 우선
- 행사 상품 제외
- 3분 이내 조리
- 전자레인지 사용 가능
- 온수 사용 가능
- 고단백 우선

영양정보가 없는 상품의 고단백 여부를 임의로 단정하지 않는다.

실행 버튼: `내 예산으로 꿀조합 찾기`

선택한 가상 매장의 상품 데이터와 조건을 사용해 추천 결과를 생성한다.

## 9. 자체 규칙 기반 꿀조합 추천 엔진

Gemini API를 호출하지 않는다. 로컬 규칙 기반 추천 알고리즘을 구현한다.

추천 기준:
1. 사용자가 선택한 예산을 초과하지 않는다.
2. 현재 가상 재고가 있는 상품만 추천한다.
3. 맛 테마와 상품 태그가 일치하는 조합을 우선한다.
4. 식사 상황에 적합한 조합을 우선한다.
5. 행사 우선 조건이 있으면 해당 행사 상품을 우선 고려한다.
6. 3분 이내 조건을 선택하면 조리 시간이 조건에 맞는 조합만 추천한다.
7. 한 끼 식사인 경우 주식·단백질·곁들임의 조합을 우선 고려한다.
8. 상품 수가 지나치게 많지 않고 이해하기 쉬운 조합을 우선한다.
9. 동일 조합이 중복 출력되지 않도록 한다.
10. 추천 가능한 조합이 없으면 조건을 완화하거나 예산을 조정하라고 안내한다.

가능한 경우 최대 3개 조합을 추천한다. 조건을 만족하는 조합이 1개뿐이라면 1개만 보여주며 존재하지 않는 조합을 억지로 채우지 않는다.

추천 카드:
- 메뉴 이름과 한 줄 설명
- 구성 상품과 수량
- 개별 가격 및 행사 할인 내역
- 총 예상 금액과 남은 잔액
- 예상 조리 시간
- 추천 이유
- `상세 레시피 보기`
- `장바구니 담기`

### 추천 예시

**치즈 불닭 계란범벅**

| 상품 | 수량 | 금액 |
|---|---:|---:|
| 불닭볶음면 | 1 | 1,800원 |
| 스트링치즈 | 1 | 1,500원 |
| 훈제란 1구 | 1 | 1,000원 |
| 합계 | | 4,300원 |

- 예산: 5,000원
- 잔액: 700원
- 예상 조리 시간: 약 3분

이 조합은 초기 샘플 상품 가격에 기반한 데모 예시다.

### 추천과 계산 분리

추천 엔진은 상품 ID와 조합 이유를 만든다. 가격 계산 모듈은 상품 DB를 다시 조회해 가격, 행사, 수량, 총액, 잔액을 계산한다. 추천 엔진이 반환한 금액을 그대로 신뢰하지 않는다.

## 10. 상세 레시피 화면

추천 카드에서 상세 레시피를 선택하면 상세 화면으로 이동한다.

표시 내용:
- 메뉴명과 대표 이미지
- 구성 상품 목록
- 준비 시간 및 총 조리 시간
- 단계별 조리 방법
- 전자레인지/온수 사용 여부
- 조리 시 주의사항
- 구매 체크리스트
- 장바구니 담기 버튼

레시피 예시: **치즈 불닭 계란범벅**
1. 불닭볶음면을 포장지 안내에 따라 조리한다.
2. 조리된 면에 소스를 넣고 잘 섞는다.
3. 스트링치즈와 훈제란을 곁들인다.
4. 필요한 경우 상품 포장지의 가열 안내를 따르고 충분히 가열되었는지 확인한다.

실제 상품 포장지의 조리 지침을 우선하도록 안내한다. 영상 URL이 제공되지 않았다면 가짜 영상 링크를 만들지 말고 텍스트 레시피를 제공한다.

## 11. 장바구니 및 예산 계산 화면

기능:
- 상품 추가 및 삭제
- 수량 변경
- 재고 수량 검증
- 행사 조건 자동 적용
- 구매 체크리스트
- 상품별 금액 및 할인 금액
- 총 결제 예상 금액
- 남은 잔액
- 예산 초과 여부
- 가상 구매 완료 버튼

계산 공식:

```text
상품별 금액 = 행사 조건을 반영한 상품 가격 × 수량
총 결제 금액 = 모든 상품별 금액의 합계
남은 잔액 = 설정 예산 - 총 결제 금액
```

예산 초과 시 초과 금액을 표시하고 가상 구매 완료를 막는다. 상품을 삭제하거나 수량을 변경하면 즉시 재계산한다.

체크리스트의 체크 상태는 구매 준비 상태일 뿐 실제 결제 완료 상태가 아니다.

## 12. 가상 구매 완료 및 영수증

사용자가 `가상 구매 완료`를 누르면 실제 결제 없이 시뮬레이션한다.

처리 순서:
1. 장바구니 상품의 현재 재고를 다시 확인한다.
2. 재고가 충분하고 예산 이내인 경우에만 완료한다.
3. 구매 수량만큼 가상 재고를 차감한다.
4. 가상 구매 내역을 기록한다.
5. 영수증 화면으로 이동한다.

영수증 구성:
- 매장명
- `가상 구매 영수증` 표시
- 구매 일시
- 상품명 및 수량
- 상품별 금액
- 행사 할인 내역
- 총 결제 금액
- 사용 예산
- 남은 잔액
- `다시 추천받기` 버튼
- `가상 매장으로 돌아가기` 버튼

실제 카드 결제, 현금 결제, 주문 접수, GS25 주문 시스템과의 연동은 하지 않는다.

## 13. 가상 매장 내 내비게이션

가상 매장 공간 안에서 다음 메뉴로 쉽게 이동할 수 있게 한다.

- 매장 홈
- 상품 보기
- 행사 상품
- 꿀조합 추천
- 장바구니

모바일에서는 하단 내비게이션을 사용하고, 데스크톱에서는 상단 탭 또는 사이드 내비게이션을 사용한다. 각 화면에서 현재 선택된 매장명과 `가상 매장` 표시를 유지한다. 기존 앱의 상단 헤더와 뒤로 가기 동작은 유지한다.

## 14. 디자인 가이드

기존 앱의 크림색 배경, 초록색, 주황색 포인트를 유지한다.

- 메인 그린: `#319447`
- 포인트 오렌지: `#F49A24`
- 크림 배경: `#FFF9EF`
- 보조 옐로: `#FFD65A`
- 본문 텍스트: `#252525`
- 카드 배경: `#FFFFFF`
- 테두리: 연한 베이지 계열

실제 쇼핑 앱처럼 직관적인 상품 카드, 충분한 여백, 읽기 쉬운 가격 표시, 명확한 행사 배지, 모바일 우선 반응형 디자인을 적용한다. 가상 데이터 안내는 숨기지 말고 명확하게 표시한다.

## 15. 오류 및 예외 처리

| 상황 | 처리 |
|---|---|
| 상품 목록이 비어 있음 | 샘플 데이터 초기화 안내 |
| 상품 검색 결과 없음 | 검색어 변경 안내 |
| 품절 상품 선택 | 장바구니 추가 차단 |
| 재고보다 많은 수량 | 가능한 최대 수량 안내 |
| 행사 수량 미충족 | 정상 가격 표시 |
| 예산 초과 | 초과 금액 표시 및 구매 차단 |
| 추천 조합 없음 | 조건 완화 또는 예산 변경 제안 |
| 레시피 정보 없음 | 정보 없음 표시 |
| 새로고침 | 가상 재고와 장바구니 상태 복원 |
| 구매 중 재고 부족 | 구매 취소 및 재고 갱신 안내 |

## 16. 코드 구조 및 유지보수

기존 프로젝트의 프레임워크와 폴더 구조를 먼저 확인하고 존중한다. 불필요하게 전체 코드를 재작성하지 않는다.

가능하면 다음 책임을 분리한다.

- `storeData`: 가상 매장 데이터
- `productData`: 상품 초기 데이터
- `promotionData`: 행사 데이터
- `inventoryService`: 가상 재고 조회 및 차감
- `recommendationEngine`: 규칙 기반 조합 추천
- `pricingService`: 가격·행사·예산 계산
- `cartService`: 장바구니 상태 관리
- `recipeData`: 레시피 데이터
- 화면 컴포넌트: 매장 홈, 상품 목록, 행사 목록, 추천 입력, 추천 결과, 레시피, 장바구니, 영수증

실제 파일명은 현재 프로젝트 구조에 맞춰 결정한다. 상품·재고 데이터는 나중에 Firestore로 교체할 수 있도록 UI에서 직접 하드코딩하지 않는다.

## 19. 최종 실행 지시
